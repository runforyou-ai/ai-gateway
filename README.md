# 轻量级 AI 网关

AI Gateway 是一个以模型为中心的统一 AI API 网关，支持多类型 AI 模型接入、多供应商管理、多协议透传、智能路由、负载均衡及统一计费。

系统通过统一模型目录和 API 接入层，为大语言模型、向量模型、语音模型、图像模型、视频模型及其他 AI 服务提供统一的访问入口。

## 核心设计

系统采用 **Model First** 架构，以模型作为核心管理对象，将模型、供应商、API 协议和服务端点解耦。

每个模型可以关联多个供应商，每个供应商可以通过一种或多种协议提供该模型的服务。各端点独立配置上游模型标识符、协议、能力、价格、限制及路由参数。

客户端通过统一模型标识符调用 AI 服务，无需感知实际供应商。

**第一期仅支持协议透传，不进行跨协议转换。** 请求根据客户端使用的协议匹配对应的供应端点，保持原生请求与响应格式。

## 模型类型

| 类型 | 功能 |
|---|---|
| Text Generation | 文本生成、对话、推理、工具调用 |
| Embedding | 文本及多模态向量生成 |
| Reranking | 文档重排序、相关性评分 |
| Image | 图像生成、编辑、理解 |
| Audio | 语音识别、语音合成、音频理解与生成 |
| Video | 视频生成、编辑、理解 |
| Multimodal | 多模态输入输出 |
| Other | 其他 AI 推理任务及自定义类型 |

## 核心功能

- **统一模型管理**：维护模型目录、模型类型、统一标识符及能力定义。
- **多供应商接入**：同一模型支持关联多个供应商及服务端点。
- **多协议透传**：支持 OpenAI、Anthropic、Gemini 等主流 API 协议，保持原生请求及响应格式。
- **端点能力管理**：独立配置各端点支持的协议、任务类型、输入输出模态及模型能力。
- **智能路由**：根据协议兼容性、价格、延迟、可用性、优先级及权重选择端点。
- **负载均衡**：支持多端点流量分配、健康检查及故障转移。
- **统一计费**：支持 Token、请求次数、字符、音频时长、图像数量、视频时长等计量方式。
- **额度与限流**：支持 API Key、模型、供应商及端点级别的额度和限流配置。
- **调用监控**：记录请求状态、延迟、错误率、用量及成本。

## 系统架构

| 模块 | 职责 |
|---|---|
| Model Registry | 模型目录、分类、统一标识符及能力定义 |
| Provider Registry | 供应商、认证凭证及连接配置 |
| Endpoint Registry | 模型供应端点、协议、价格及能力配置 |
| Protocol Handler | 协议识别、原生请求透传及响应处理 |
| Routing Engine | 端点筛选、负载均衡、智能路由及故障转移 |
| Usage & Billing | 用量统计、成本核算、配额及计费 |
| Observability | 调用日志、性能指标及健康监控 |

## 请求处理流程

1. 根据客户端提交的模型标识符定位目标模型。
2. 识别请求协议、任务类型及所需能力。
3. 获取模型关联的供应端点。
4. 筛选协议一致、能力匹配且处于可用状态的端点。
5. 根据路由策略选择目标端点。
6. 替换上游模型标识符及必要的连接认证信息，透传请求。
7. 原生返回上游响应，记录用量、成本及调用状态。

不同协议之间不进行自动转换。不存在兼容端点时，返回明确错误。

## 设计原则

- **模型优先**：以模型为核心组织供应商、协议和服务端点。
- **模型类型无关**：统一管理不同类型的 AI 模型及推理任务。
- **供应商解耦**：同一模型可由多个供应商提供，支持独立配置和动态切换。
- **协议独立**：协议作为端点属性管理，同一模型支持不同协议的供应端点。
- **原生透传**：保持协议语义、请求参数、流式响应及模型特性，不执行跨协议转换。
- **配置驱动**：通过标准协议及端点配置扩展供应商，减少专用适配代码。
- **能力感知**：根据端点实际支持的协议及能力进行路由。
- **统一计量**：针对不同模型类型采用相应的用量统计和计费方式。
- **高可用性**：通过多供应商冗余、负载均衡及故障转移提高服务稳定性。

## 开发阶段

### 第一阶段

实现以模型为中心的管理体系、多供应商接入、多协议原生透传、智能路由、负载均衡、用量统计及统一计费。

### 后续扩展

根据需求增加跨协议转换、模型能力映射、高级路由策略及更多模型服务协议。

跨协议转换作为独立扩展能力，不影响现有的模型、供应商及端点管理结构。
