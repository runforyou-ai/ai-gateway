# 轻量级 AI 网关

AI Gateway 是一个以模型为中心的统一 AI API 网关，支持多类型 AI 模型接入、多供应商管理、多协议透传与协议转换、智能路由、负载均衡及统一计费。

系统通过统一模型目录和 API 接入层，为大语言模型、向量模型、语音模型、图像模型、视频模型及其他 AI 服务提供统一的访问入口。

许可证：[MIT](LICENSE)

## 核心设计

系统采用 **Model First** 架构，以模型作为核心管理对象，将模型、供应商、API 协议和服务端点解耦。

每个模型可以关联多个**平台预设供应商**（不支持自定义供应商）。各端点在预设能力范围内配置上游模型标识符、凭证、价格、限制及路由参数。

平台对每个对外模型提供一组**标准协议入口**（如 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 等）。客户端通过统一模型标识符与所选协议调用，无需感知实际供应商。

### 透传与协议转换

- **预设供应商**：平台内置一组供应商定义；每种预设固定其原生协议，以及允许对外暴露的协议（含是否经转换）。
- **开关写死在预设里**：协议透传 / 转换能力由代码中的预设决定，管理员不可改开关，也不可新增供应商类型。
- **同协议透传**：客户端协议属于该供应商原生协议时，请求与响应保持原生格式转发。
- **跨协议转换**：客户端协议属于该预设「可转换对外协议」时，由 [RelayKit](https://github.com/QuantumNous/new-api/tree/main/relaykit) 转换后再转发；不在预设范围内则返回明确错误。

示例：预设供应商 OpenAI 原生支持 Completions 与 Responses，并在预设中固定开启向 Gemini / Anthropic 客户端协议的转换。模型绑定该供应商后，客户端可用上述协议调用，无需在管理台再配转换开关。

## 模型类型

| 类型 | 功能 |
|---|---|
| Text Generation | 文本生成、对话、推理、工具调用 |
| Embedding | 文本及多模态向量生成 |
| Reranking | 文档重排序、相关性评分 |
| Image | 图像生成、编辑、理解 |
| Audio | 语音识别、语音合成、音频理解与生成 |
| Video | 视频生成、编辑、理解 |
| Multimodal | 多模态输入输出 |
| Other | 其他 AI 推理任务及自定义类型 |

## 核心功能

- **统一模型管理**：维护模型目录、模型类型、统一标识符及能力定义。
- **预设供应商接入**：同一模型可关联多个平台预设供应商及服务端点；不支持自定义供应商。
- **多协议接入**：对外提供标准协议；按预设决定透传或经 RelayKit 转换。
- **端点配置**：在预设能力内配置上游标识、凭证、价格、限制及路由参数（不含转换开关）。
- **智能路由**：根据预设协议能力、价格、延迟、可用性、优先级及权重选择端点。
- **负载均衡**：支持多端点流量分配、健康检查及故障转移。
- **统一计费**：支持 Token、请求次数、字符、音频时长、图像数量、视频时长等计量方式。
- **额度与限流**：支持 API Key、模型、供应商及端点级别的额度和限流配置。
- **调用监控**：记录请求状态、延迟、错误率、用量及成本。

## 系统架构

| 模块 | 职责 |
|---|---|
| Model Registry | 模型目录、分类、统一标识符及能力定义 |
| Provider Registry | 平台预设供应商、认证凭证及连接配置 |
| Endpoint Registry | 模型供应端点、价格及路由等可配项（协议能力来自预设） |
| Protocol Handler | 协议识别、按预设透传或转换及响应处理 |
| Routing Engine | 端点筛选、负载均衡、智能路由及故障转移 |
| Usage & Billing | 用量统计、成本核算、配额及计费 |
| Observability | 调用日志、性能指标及健康监控 |

## 请求处理流程

1. 根据客户端提交的模型标识符定位目标模型。
2. 识别请求协议、任务类型及所需能力。
3. 获取模型关联的供应端点。
4. 筛选处于可用状态、能力匹配，且客户端协议在该**预设供应商**允许范围内（原生或可转换）的端点。
5. 根据路由策略选择目标端点。
6. 替换上游模型标识符及连接认证信息；同协议则透传，否则按预设执行协议转换后转发。
7. 将上游响应按客户端协议返回（必要时再转换），并记录用量、成本及调用状态。

## 设计原则

- **模型优先**：以模型为核心组织供应商、协议和服务端点。
- **模型类型无关**：统一管理不同类型的 AI 模型及推理任务。
- **预设供应商**：仅支持平台内置供应商；协议透传/转换矩阵写死在预设中，管理台不可改、不可扩展供应商类型。
- **供应商解耦**：同一模型可绑定多个预设供应商实例（凭证与端点），支持独立配置和动态切换。
- **协议独立**：对外标准协议与上游原生协议可分离；是否转换由预设决定。
- **能力感知**：根据预设的协议能力及端点状态进行路由。
- **统一计量**：针对不同模型类型采用相应的用量统计和计费方式。
- **高可用性**：通过多供应商冗余、负载均衡及故障转移提高服务稳定性。

## 技术概要

| 项 | 说明 |
|---|---|
| 后端 | Go，标准库 `net/http`，Cobra CLI；Action + 契约（`contract` / `contractgen`） |
| 协议转换 | RelayKit；矩阵写死在预设供应商 |
| 数据 | PostgreSQL（goose 迁移 + bun）；NATS JetStream（jetcast 广播、jetq 后台任务） |
| NATS | 未配置 `nats.url` 时嵌入 nats-server；配置后连接独立或集群 |
| 前端 | Refine + shadcn/ui + Tailwind CSS；`/api` 客户端由契约生成；产物嵌入单一 Linux 二进制 |
| 认证 | 管理台 Cookie + `sessions`；对外 `/v1` 用 API Key；角色仅 `admin` / `user` |
| 配置 | yaml 仅启动/基础设施；系统级 `settings` / `state` 存库（按名 JSON 文档组） |
| 配置文件 | `init` 生成 yaml（有 `.env` 则覆盖默认值）；`serve` 只读 yaml |
| 注册 | `POST /api/register`；首个用户自动为 admin，其后需开放注册 |
| Make | `make dev` 同时起前后端；`make build` 打当前系统包；`make build amd64\|arm64` 打 Linux 包 |
| Docker | 生产单机：`make build amd64\|arm64` 后 `docker compose up --build`（挂载根目录 `config.yaml`；镜像嵌入对应 Linux 二进制） |
| CI / CD | PR/`main` 校验与 compose 冒烟；`main` 推送 `latest`；打 tag `v*` 发布 Release 与版本镜像（amd64+arm64） |
| 进程 | `serve` / `stop` / `restart` / `reload`；pid 默认与配置同目录 |
| 日志 | `slog`；控制台按行输出；文件轮转：开发 `./data/logs/`，生产 `/var/log/lite-ai-gateway/`（yaml 可覆盖） |
| API | `/v1/*` 对外 AI（手写）；`/api/*` 管理台（契约生成） |

仅面向 **Linux** 部署与发布。

## 开发阶段

### 第一阶段

### 后续扩展

根据需求增加模型能力映射、高级路由策略、更多预设供应商及模型服务协议。
