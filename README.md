# AI Gateway

以模型为中心的统一 AI API 网关。把大语言模型、向量、语音、图像、视频等能力收进同一套入口，对接平台预设的云厂商，支持多协议透传与转换、智能路由、负载均衡和统一计费。一个程序即可运行，管理界面打在程序里。

客户端只用统一的模型名和常见协议（如 OpenAI Chat Completions / Responses、Anthropic Messages、Gemini 等）即可调用，不必关心背后实际走哪家供应商。

不支持自定义供应商；协议透传 / 转换矩阵写死在预设中，管理台不可改开关、不可新增供应商类型。

## 核心设计

系统按 **模型优先（Model First）** 组织：模型是中心，供应商、协议和服务端点拆开配置。

- 每个模型可挂多个**平台预设供应商**（不支持自定义供应商类型）。
- 每个端点在预设能力范围内配置：上游模型名、密钥、价格、限额和路由参数。
- 每种预设供应商写死原生协议，以及允许对外暴露的协议（含是否做转换）。管理员不能改这些开关，也不能新增供应商种类。

### 透传与协议转换

- **同协议透传**：客户端协议正好是该供应商的原生协议时，请求和响应按原样转发。
- **跨协议转换**：客户端协议在该预设允许的「可转换」列表里时，经 [RelayKit](https://github.com/QuantumNous/new-api/tree/main/relaykit) 转换后再转发；不在列表里则返回明确错误。

举例：预设「OpenAI」原生支持 Completions 与 Responses，并固定允许用 Gemini / Anthropic 客户端协议来调。模型绑上该供应商后，客户端可直接用这些协议，无需在管理台再开转换开关。

## 支持的模型类型

| 类型 | 说明 |
|---|---|
| Text Generation | 文本生成、对话、推理、工具调用 |
| Embedding | 文本及多模态向量 |
| Reranking | 文档重排序、相关性评分 |
| Image | 图像生成、编辑、理解 |
| Audio | 语音识别、合成，以及音频理解与生成 |
| Video | 视频生成、编辑、理解 |
| Multimodal | 多模态输入输出 |
| Other | 其他推理任务 |

## 主要能力

- **统一模型管理**：模型目录、类型、统一标识和能力定义。
- **预设供应商接入**：同一模型可挂多个预设供应商及端点。
- **多协议接入**：对外提供标准协议；按预设决定透传或转换。
- **端点配置**：上游标识、凭证、价格、限额、路由参数（不含转换开关）。
- **智能路由**：按协议能力、价格、延迟、可用性、优先级和权重选端点。
- **负载均衡**：多端点分流、健康检查、故障转移。
- **统一计费**：按 Token、次数、字符、音视频时长、图像张数等计量。
- **额度与限流**：可按 Virtual Key、模型、供应商、端点配置。
- **调用监控**：状态、延迟、错误率、用量与成本。

## 系统组成

| 模块 | 做什么 |
|---|---|
| Model Registry | 模型目录与能力 |
| Provider / Endpoint Registry | 预设供应商实例、端点与可配项 |
| Protocol Handler | 协议识别、透传或转换 |
| Routing Engine | 筛选、均衡、故障转移 |
| Usage & Billing | 计量、配额、计费 |
| Observability | 调用日志与指标 |

## 一次请求怎么走

1. 按客户端提交的模型名找到模型。
2. 识别协议、任务类型和所需能力。
3. 取出该模型下的供应端点。
4. 筛出可用、能力匹配、且客户端协议在该预设供应商允许范围内（原生或可转换）的端点。
5. 按路由策略选定端点。
6. 换成上游模型名和凭证；同协议则透传，否则按预设转换后转发。
7. 按客户端协议返回响应（必要时再转换），并记下用量、成本和调用结果。

## 设计原则

- **模型优先**：围绕模型组织供应商、协议和端点。
- **类型无关**：文本、向量、音视频等同一套管理方式。
- **仅预设供应商**：透传 / 转换矩阵写死在预设里，管理台不可改、不可扩展供应商类型。
- **供应商解耦**：同一模型可绑多个预设实例，独立配置、可切换。
- **协议独立**：对外协议与上游原生协议可分离，是否转换由预设决定。
- **能力感知**：按预设协议能力与端点状态路由。
- **统一计量**：按模型类型选用合适的计量方式。
- **高可用**：多供应商冗余、均衡与故障转移。

## 运行与部署

面向 Linux。配置文件由 `init` 生成（可用当前目录 `.env` 覆盖默认值），`serve` / `reload` 只读 yaml；默认路径为 `~/.config/ai-gateway/config.yaml`（或 `$XDG_CONFIG_HOME/ai-gateway/config.yaml`）。

```bash
go run . init
make dev backend                  # 后端（另开终端）
make dev frontend                 # 管理台 Vite
go run . stop                     # 停止后端
make build                        # 当前机器二进制
make build amd64                  # 或 arm64，供 Linux / Docker
docker compose up --build         # 需先按宿主机架构完成交叉编译
```

镜像：`ghcr.io/runforyou-ai/ai-gateway`。进程命令：`serve` / `stop` / `restart` / `reload`。

管理台用浏览器登录（Cookie 会话）；调用 AI 接口使用 Virtual Key。角色只有管理员与普通用户；系统里第一个注册的用户自动成为管理员。
